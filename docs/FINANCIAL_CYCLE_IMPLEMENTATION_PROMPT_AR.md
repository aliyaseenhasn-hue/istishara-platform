# برومت تنفيذ الدورة المالية الكاملة لتطبيق استشارة

نفّذ دورة مالية كاملة وآمنة لتطبيق استشارة المبني بـFlutter + Supabase + Qi Card، مع الحفاظ على منطق الحجز والدفع الحالي وعدم كسر أي ميزة قائمة.

## الأهداف
1. تسجيل كل دفعة إلكترونية ناجحة في Qi Card كعملية مالية موثقة.
2. فصل المبلغ الإجمالي عن عمولة المنصة وصافي مستحق المحامي.
3. إنشاء Ledger مالي غير قابل للتكرار يعتمد على idempotency keys.
4. إنشاء محفظة داخلية لكل محامٍ توضح المتاح والمعلق وإجمالي الأرباح والمسحوبات.
5. إنشاء طلبات سحب للمحامي مع مراجعة الإدارة.
6. ربط غرامات إلغاء المحامي بالدفع المستقبلي وتسجيلها كخصم من مستحق المحامي ورصيد تعويض للعميل.
7. منع تكرار إضافة أرباح المحامي عند تكرار Webhook أو تحديث حالة الدفع.
8. توفير لوحة إدارة مالية لعرض الدفعات والعمولات وأرصدة المحامين وطلبات السحب وسجل العمليات.
9. جعل نسبة العمولة قابلة للضبط من الإدارة، وعدم افتراض نسبة تجارية غير معتمدة؛ القيمة الافتراضية الآمنة 0% إلى أن تضبط الإدارة النسبة.
10. عدم الادعاء بأن الأموال تنتقل فعلياً إلى محفظة المحامي إلا بعد توفر API/اعتماد مزود التحويل؛ عند عدم توفره يكون طلب السحب Manual/Pending Review.

## دورة الدفع
العميل → Qi Card → حساب التاجر المرتبط بـQi Card → payments → payment_financials → financial_ledger → رصيد المحامي/إيراد المنصة.

## الحساب
Gross = مبلغ الدفع.
Platform Commission = Gross × commission_rate / 100.
Lawyer Net = Gross - Platform Commission - Penalty Allocation.

يجب حفظ النسبة والمبالغ المحسوبة لحظة الدفع، حتى لا تتغير العمليات التاريخية عند تغيير نسبة العمولة لاحقاً.

## الغرامات والتعويضات
عند فرض غرامة على محامٍ بسبب إلغاء حجز:
- lawyer_penalties يحتفظ بالالتزام.
- عند الدفع المستقبلي يتم تحصيل الغرامة مرة واحدة فقط.
- تخصم الغرامة من رصيد المحامي.
- تسجل client_credit للعميل.
- تسجل financial_ledger entries للغرامة والتعويض.
- لا يعتبر الرصيد الداخلي تحويلاً مصرفياً فعلياً للعميل حتى يوجد مسار Refund/Payout حقيقي.

## السحب
المحامي يطلب سحب مبلغ من available_balance إلى wallet_number.
يصبح المبلغ pending_balance.
الإدارة توافق/تعالج/تدفع أو ترفض.
عند الرفض يعاد المبلغ إلى available_balance.
عند الدفع يسجل lifetime_paid_out.

## الاسترداد
لا تغيّر حالة الدفع إلى refunded إلا عند وجود إثبات لتنفيذ Refund فعلي لدى Qi Card. إذا لم يتوفر API الاسترداد، استخدم حالة طلب استرداد منفصلة ومراجعة الإدارة ولا تزور حالة الدفع.

## الأمان
- كل وظائف الإدارة SECURITY DEFINER مع تحقق role=admin.
- RLS على الجداول المالية.
- لا تسمح للعميل أو المحامي بتعديل Ledger مباشرة.
- استخدم unique idempotency_key لمنع التكرار.
- لا تخزن أسرار Qi Card في Flutter أو قاعدة البيانات العامة.
- لا تنفذ تحويلات مالية فعلية من التطبيق دون اعتماد API رسمي للمزود.

## الواجهات
أضف للمحامي صفحة المحفظة: الرصيد المتاح، الرصيد المعلق، إجمالي الأرباح، إجمالي المسحوبات، رقم المحفظة، طلب سحب.
أضف للإدارة صفحة مالية: إجمالي المدفوعات، عمولة المنصة، صافي مستحقات المحامين، التعويضات، الغرامات، طلبات السحب، وتفاصيل Ledger.

## الاختبارات الإلزامية
- Webhook مكرر لا يضاعف رصيد المحامي.
- الدفع الملغي لا يضيف أرباحاً.
- تغيير العمولة لا يغير دفعات قديمة.
- الغرامة لا تحصل مرتين من نفس الدفع.
- السحب لا يتجاوز الرصيد.
- رفض السحب يعيد الرصيد.
- الدفع الإلكتروني والدفع المكتبي يبقيان مسارين منفصلين.
- Refund غير المؤكد لا يحوّل حالة الدفع إلى refunded.
